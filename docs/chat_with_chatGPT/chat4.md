أوافق على الإصلاح، وأعتقد أن هذا **Bug حقيقي** وليس مجرد تعديل تجميلي.

السبب واضح:

عند إنشاء النسخة الاحتياطية كنت تكتب الملف بصيغة معيارية مثل:

```text
bf6c025892870ebd5cdc7c05fff91c54562306671c225ff833df77e20fd070c6  backup_2026-07-28_16-56-47.tar.gz
```

وهذه هي صيغة أداة `sha256sum` في لينكس.

لكن أثناء الاستعادة كنت تقرأ السطر كاملًا وتقارنه مع قيمة الـ SHA المخزنة في قاعدة البيانات:

```text
"bf6c0258...  backup.tar.gz"
```

مقابل

```text
"bf6c0258..."
```

وهذا سيؤدي دائمًا إلى فشل المقارنة حتى لو كانت النسخة سليمة.

---

## الإصلاح الصحيح

استخراج أول حقل فقط:

```ts
const storedLine = (await fsp.readFile(checksumFile, 'utf-8')).trim();
const storedChecksum = storedLine.split(/\s+/)[0];
```

هذا يجعل النظام متوافقًا مع الصيغة القياسية لـ `sha256sum`.

---

## لكن أقترح تحسينًا صغيرًا

بدلًا من:

```ts
storedLine.split(/\s+/)[0]
```

أفضل:

```ts
const [storedChecksum] = storedLine.trim().split(/\s+/, 1);
```

أو حتى:

```ts
const match = storedLine.match(/^([a-fA-F0-9]{64})/);

if (!match) {
    throw new Error('Invalid checksum file format');
}

const storedChecksum = match[1];
```

لأن هذا يتحقق أيضًا من أن الملف يحتوي فعلًا على SHA-256 صالح، وليس أي نص.
